# Known limits

States Subclave accepts on purpose. Each entry says what is accepted, where it
lives, and what would change it.

## Sync

- **Tombstones expire after 90 days**: a deleted entry or group comes back when a device that still holds it was offline for more than 90 days, because past that window a tombstone is neither published nor read. Each device prunes only the remote tombstones it published itself, so the tombstones of a device that is never used again stay on the remote for good. `src-tauri/src/modules/sync/engine/layout.rs` (`TOMBSTONE_TTL_MS`). Changes when: devices can be retired from the remote, or a prune can act on another device's tombstones.
- **Keyfile race without conditional writes**: two devices that set up sync on the same empty remote at the same moment can both write a keyfile. A backend that cannot honour a conditional create stores the second over the first, and the device that wrote first then holds a root key the stored keyfile no longer opens. S3 sends `If-None-Match: *` only when the endpoint is set as supporting conditional writes; WebDAV always sends it and cannot rely on the server honouring it. `src-tauri/src/modules/sync/provider.rs` (`put_if_absent`). Changes when: a keyfile write is verified by reading it back before the root key is used.
- **The sync switch is enforced in the webview**: Rust's `sync_pull` and `sync_push` do not read the on/off switch; they refuse only while no sync session is open. The scheduler checks the switch before every pass. `src/modules/sync/scheduler/policy.ts` (`runPull`, `runPush`, the `config.enabled` checks). Changes when: the switch is stored where Rust reads it.
- **Same-millisecond edits keep one copy**: when two devices stamp an edit to one entry in the same millisecond, the merge picks the winner by content and records no `conflict` version for the loser, and the history dedupe keeps one version per stamp. `src-tauri/src/modules/vault/merge_history.rs` (`merge_entries`, the equal-stamp branch, and `dedupe_and_cap`). Changes when: versions are keyed by more than their stamp.
- **A fast clock wins every conflict**: the newer stamp decides which copy stays current, so a device whose clock runs ahead wins every conflict. The losing copy is kept in history as `conflict`, and there is no clock-skew warning. `src-tauri/src/modules/vault/merge_history.rs` (`merge_entries`). Changes when: a pull compares the remote's time with the local clock and warns.
- **WebDAV pushes race**: WebDAV has no reliable conditional write, so two devices pushing one record at once both succeed and the later write overwrites the earlier. The overwritten device sees the changed object on its next pull, merges, and pushes the result again. `src-tauri/src/modules/sync/providers/webdav/mod.rs` (`put`), `src-tauri/src/modules/sync/engine/mod.rs` (`push`). Changes when: WebDAV servers can be relied on to honour `If-Match`.

## Vault and memory

- **Zeroization leftovers**: the payload and the key are wiped on lock, but some copies of secrets are not scrubbed when they are freed. Changes when: each of these paths moves to a zeroizing type.
  - `aesgcm::seal_with_key` copies the plaintext into a plain `Vec` and encrypts that copy in place, so it holds ciphertext once the seal returns; a seal that fails drops it unscrubbed. `src-tauri/src/modules/aesgcm.rs` (`seal_with_key`).
  - Sync records pass through `serde_json::Value`, whose strings are not zeroized. `src-tauri/src/modules/sync/model.rs` (`Envelope`, `record`).
  - The merge builds whole records, secrets included, as plain `String`s to order them. `src-tauri/src/modules/vault/merge_history.rs` (`canonical`), `src-tauri/src/modules/sync/model.rs` (`canonical`).
  - The WebDAV `Authorization` header is a plain `String` holding the password in base64. `src-tauri/src/modules/sync/providers/webdav/build.rs` (`basic_auth`).
  - CSV import and export pass the file through `csv::StringRecord` and plain `String`s, and the CSV writer's buffer is not scrubbed. `src-tauri/src/modules/import/formats.rs` (`parse_csv`), `src-tauri/src/modules/import/export.rs` (`csv_bytes`).
  - JavaScript strings in the webview (a revealed password, the master password while it is typed) cannot be zeroized.
- **No lock on suspend or screen lock**: Subclave does not lock when the machine sleeps or the screen locks, so hibernating while unlocked writes the key to disk with the rest of memory. The idle lock runs on a clock that counts sleep and fires within 5 s of waking past the deadline. `src-tauri/src/modules/vault/lock.rs` (`boot_now_ms`). Changes when: the app listens for the platform's suspend and screen-lock signals.
- **Linux clipboard history**: a secret copy carries the KDE password-manager hint, but a clipboard manager that ignores it can keep the value in its history. Auto-clear is the mitigation. `src-tauri/src/modules/clipboard.rs` (`write_text`). Changes when: a desktop-wide way to keep a value out of clipboard history exists.

## Browser extension

- **No fill in cross-origin iframes**: the content script runs in the top frame only and reaches same-origin iframes through `contentDocument`, which a cross-origin frame does not expose, so a login form inside one is neither detected nor filled. `extension/src/content/fill.ts` (`rootsOf`). Changes when: the content script runs in every frame with a per-frame origin check.
- **The inline guards are JavaScript against JavaScript**: the six clickjacking guards run in the same page as the code they guard against, and Firefox has no `IntersectionObserver` v2, so the visibility guard (guard 6) runs on Chromium only. `extension/src/content/guard.ts` (`createGuard`). Changes when: browsers give extension UI a visibility guarantee.
- **No inline UI without the Popover API**: Firefox 115 to 124 (and Chrome before 114) get no icon in login fields and no save prompt; the popup and the fill command still work. The save prompt is part of the inline UI, so "Show in login fields" off turns it off too. `extension/src/content/inline.ts` (`startInline`). Changes when: the minimum Firefox version reaches 125.
- **Very late login forms get no icon**: a page with no login field 5 seconds after it has loaded stops watching for good, so a single-page app that shows its login form later (or navigates to it without a page load) gets no icon. The popup and the fill command still fill it. `extension/src/content/inline.ts` (`SETTLE_AFTER_LOAD_MS`, `settle` in `createInline`). Changes when: detection keeps a cheap watch running on pages without a field.
- **An unhinted first login step gets no icon**: a text field on its own (the first step of a two-step login) gets an icon only when it says `autocomplete="username"` or `"email"`, which keeps icons out of search boxes and newsletter fields. A first step without the hint (Yahoo and Zoom when last checked) gets no icon; the popup and the fill command still fill it. `extension/src/content/detect.ts` (`scan`). Changes when: detection gets a name or label heuristic that still leaves search and newsletter fields alone.
- **"Show in login fields" applies from the next page load**: the content script reads the setting once when the page loads, so open tabs keep their current state. `extension/src/content/index.ts` (`askSettings`). Changes when: the service worker tells open tabs about the change.
- **No save prompt for password-only forms**: a submitted form is offered for saving only when it holds a username next to the filled password, so the second step of a two-step login, and a change-password form without a username field, get no prompt. An update from such a form would blank the stored username. `extension/src/content/inline.ts` (`submittedLogin`). Changes when: the first step's username is carried to the second.
- **No save prompt for formless or scripted sign-ins**: the submit is caught on the `<form>` itself, from its `submit` event or a click on its submit button, so a sign-in sent by script without a `<form>`, from a `type="button"` button or a non-button element, or by page script without a user gesture, is never offered. `extension/src/content/inline.ts` (`wireForm`, `SUBMIT_BUTTON`). Changes when: detection gets a formless submit rule.
- **A refused sign-in still waits to be saved**: a refused sign-in, or a click on a submit-type button that signs nothing in (a show-password toggle without `type="button"`), still leaves a pending sign-in. The page shows no prompt while the password is still in its form, but the tab's next page load offers it. `extension/src/content/inline.ts` (`wireForm`, `submitted`). Changes when: a sign-in can be told apart from a refused one.
- **A Domain-rule login still prompts on other hosts**: a login stored only under a Domain rule still gets a save prompt on another host of that domain, because the check, like every inline request, sees exact-host entries only. `src-tauri/src/modules/browser/actions.rs` (`check_login`). Changes when: wider matches get a browser-owned save path.
- **A typed password waits in session storage**: a pending sign-in is dropped after 3 page loads in its tab (loads on another site count, though the prompt shows only on the submit's site), and after 5 minutes once its tab loads another page. Until then, or until the tab closes or the browser exits, the typed password stays in `chrome.storage.session`, which the browser keeps in memory. `extension/src/background.ts` (`PENDING_SAVE_TTL_MS`, `PENDING_SAVE_PAGE_LOADS`). Changes when: the service worker can expire it on a timer that survives a restart.
- **Sandboxed browsers**: for Snap and Flatpak installs the manifests are also written into the sandboxed profile path and Settings > Browser marks them, but native messaging from Snap Firefox is not tested yet. `src-tauri/src/modules/browser/manifests.rs` (`BrowserSlot`, `sandboxed`). Changes when: a run on Snap Firefox confirms it, or shows what it needs.

## Import and backup

- **CSV import is flat**: every imported row lands in one new `Imported <date>` group. KeePassXC groups and Bitwarden folders are not recreated, and dates and icons are ignored. `src-tauri/src/modules/import/mod.rs` (`import_apply_inner`). Changes when: the import maps a folder column to a group tree.
- **Imported custom fields arrive hidden**: Bitwarden's CSV does not carry a custom field's hidden flag, so every imported custom field is hidden. `src-tauri/src/modules/import/formats.rs` (`push_field`). Changes when: an import format that carries the flag is supported.
- **Unreadable TOTP values**: a TOTP cell that parses neither as an `otpauth://` URI nor as a base32 secret is kept as a hidden custom field named `TOTP`. `src-tauri/src/modules/import/formats.rs` (`totp_of`). Changes when: the TOTP parser accepts more encodings.
- **CSV export is lossy**: it uses Bitwarden's columns, so history, tags, expiry, icon, colour, created dates, URL match modes and the hidden flag are dropped, and entries in Trash are skipped. A round trip through the CSV also splits a custom-field value that holds a line break into two fields, splits a field name that holds `": "`, and splits a URL that holds a comma, because the fields column is `name: value` lines and the URI column is comma-separated. `src-tauri/src/modules/import/export.rs` (`csv_bytes`), `src-tauri/src/modules/import/formats.rs` (`map_row`). Changes when: a plaintext format that carries those fields is added; the encrypted backup already keeps them.
- **Backups carry no tombstones**: a backup holds entries and groups only, so a restore never deletes anything. `src-tauri/src/modules/backup.rs` (`BackupPayload`). Changes when: backups record deletions.
- **A restore keeps only recent deletes**: an entry deleted here after the backup was written stays deleted while the delete is under 90 days old, because a local tombstone newer than the backup copy wins the merge. An older tombstone reads as absent, as it does for sync, so the backup copy comes back. `src-tauri/src/modules/sync/engine/payload.rs` (`local_envelope`), `src-tauri/src/modules/sync/engine/layout.rs` (`TOMBSTONE_TTL_MS`). Changes when: the restore checks tombstones of any age.
- **Same-name sibling groups after a restore**: the restore merges groups by id and skips the sibling-name clash check that `vault_group_upsert_inner` applies, so a backup group can land beside a local group of the same name. `src-tauri/src/modules/sync/engine/payload.rs` (`merge_into_payload`). Changes when: the apply renames or folds clashing groups.
- **Preview rows stay in memory**: a preview's decoded rows stay in the app's memory until the next preview, the apply, or the lock, whichever comes first. `src-tauri/src/modules/vault/state.rs` (`Staged`). Changes when: the apply re-reads the file instead of holding the rows.

## Desktop

- **Tray on Linux**: GNOME without an AppIndicator extension shows no tray icon, and Linux AppIndicator delivers no left click, so the paths back to a hidden window are "Open Subclave" in the tray menu and launching Subclave again. `src-tauri/src/modules/tray.rs` (`build`). Changes when: GNOME ships a tray host, or the window gets another way back.
- **Builds are not code-signed**: macOS builds are ad-hoc signed, so Gatekeeper blocks the first launch until the quarantine bit is cleared (`xattr -cr`), and Windows shows a SmartScreen warning. `.github/workflows/release.yml` (`APPLE_SIGNING_IDENTITY`). Changes when: a Developer ID certificate and a Windows signing certificate are in the release secrets.
- **Uninstall leaves browser manifests**: the Windows uninstaller removes the native messaging keys and manifests (`src-tauri/installer.nsh`, `NSIS_HOOK_PREUNINSTALL`), but `.deb` and `.rpm` removal, deleting an AppImage, and removing the macOS app cannot reach per-user files. Turning off both switches in Settings > Browser before uninstalling removes the manifest from every browser Subclave still detects. `src-tauri/src/modules/browser/manifests.rs` (`slots`), `README.md` (Uninstall). Changes when: the packages ship a per-user cleanup step.
